## 1. พื้นฐานและวงจรข้อมูล (Data Lifecycle)
วงจรการทำงานพื้นฐานที่วิศวกรข้อมูลต้องดูแลประกอบด้วยขั้นตอนหลักดังนี้:

* **Data Engineer Lifecycle**: เริ่มตั้งแต่การสร้างข้อมูล (Generation), การนำเข้า (Ingestion), การจัดเก็บ (Storage), การแปลงข้อมูล (Transformation) ไปจนถึงการนำไปใช้ (Serving)
* **Ingestion**: กระบวนการนำข้อมูลจากแหล่งต้นทางต่างๆ เข้ามาสู่ระบบจัดเก็บ
* **Transformation**: การปรับเปลี่ยน รูปแบบ หรือทำความสะอาดข้อมูลให้พร้อมใช้งาน
* **Serving**: การส่งต่อข้อมูลที่ประมวลผลแล้วไปให้ผู้ใช้ เช่น งานด้านการวิเคราะห์ (Analytics) หรือการประมวลผลโมเดล (Machine Learning)

## 2. รูปแบบไฟล์ข้อมูล (File Formats)
การเลือกใช้รูปแบบไฟล์ที่เหมาะสมมีผลต่อประสิทธิภาพในการประมวลผล:

* **Structured Data**: ข้อมูลที่มีโครงสร้างชัดเจนแน่นอน เช่น ตารางในฐานข้อมูล
* **Semi-structured Data**: ข้อมูลที่มีโครงสร้างระดับหนึ่งแต่ยืดหยุ่นได้ เช่น JSON, XML
* **Unstructured Data**: ข้อมูลที่ไม่มีโครงสร้างตายตัว เช่น ไฟล์เสียง, วิดีโอ, รูปภาพ
* **CSV (Comma-Separated Values)**: ไฟล์ข้อความที่ใช้เครื่องหมายจุลภาค (,) แบ่งคอลัมน์ อ่านง่าย เป็นที่นิยมแต่ใช้พื้นที่จัดเก็บมากกว่าไฟล์บีบอัด
* **JSON (JavaScript Object Notation)**: รูปแบบข้อมูลน้ำหนักเบา เก็บเป็นคู่ "Key" และ "Value" รองรับโครงสร้างซับซ้อนแบบ Nested
* **Parquet**: การเก็บข้อมูลแบบแนวตั้ง (Columnar Format) ที่มีการบีบอัดสูง รองรับ Predicate Pushdown ที่ช่วยให้อ่านเฉพาะคอลัมน์ที่ต้องการ ทำให้ทำงานได้รวดเร็ว

## 3. ระบบจัดการฐานข้อมูล (Database Systems)
ความแตกต่างของระบบฐานข้อมูลตามวัตถุประสงค์การใช้งาน:

* **OLTP (Online Transaction Processing)**: ระบบที่เน้นการทำธุรกรรม (Transaction) จำนวนมากและรวดเร็ว เก็บข้อมูลแบบแถว (Row-based) เช่น MySQL, Postgres
* **OLAP (Online Analytical Processing)**: ระบบที่เน้นการค้นหาและวิเคราะห์ข้อมูลปริมาณมาก มักเก็บข้อมูลแบบคอลัมน์ (Column-based) เช่น BigQuery, Clickhouse

## 4. สถาปัตยกรรมการจัดเก็บข้อมูล (Storage Architecture)
วิวัฒนาการของการจัดเก็บข้อมูลในระดับองค์กร:

* **Data Lake**: ที่เก็บข้อมูลดิบ (Raw Data) ขนาดมหาศาล รองรับทุกรูปแบบ มีความยืดหยุ่นสูงและราคาประหยัด
* **Data Warehouse**: ระบบจัดเก็บข้อมูลที่ผ่านการทำความสะอาดและจัดโครงสร้างแล้ว เพื่อประสิทธิภาพสูงสุดในการคิวรี
* **Data Mart**: ส่วนย่อยของ Data Warehouse ที่ออกแบบมาเพื่อตอบโจทย์เฉพาะแผนกหรือหน่วยธุรกิจ
* **Data Lakehouse**: สถาปัตยกรรมที่รวมจุดเด่นของ Data Lake (ราคาถูก, ยืดหยุ่น) และ Data Warehouse (จัดการง่าย, ประสิทธิภาพดี) เข้าด้วยกันบนแพลตฟอร์มเดียว

---

## 5. กระบวนการจัดการข้อมูล (Data Pipelines)
วิธีการเคลื่อนย้ายและจัดการข้อมูล:

* **ETL (Extract, Transform, Load)**: การดึงข้อมูลมาแปลงและทำความสะอาดให้เรียบร้อยก่อนแล้วจึงนำไปเก็บในระบบปลายทาง
* **ELT (Extract, Load, Transform)**: การดึงข้อมูลไปเก็บไว้ที่ปลายทางก่อน แล้วค่อยทำการแปลงข้อมูลในภายหลัง (นิยมใช้กับระบบ Cloud สมัยใหม่)

## 1. ภาษาสำหรับการนิยามข้อมูล (DDL - Data Definition Language)
คำสั่งที่ใช้ในการสร้างและปรับเปลี่ยนโครงสร้างของตารางในตรรกะระบบ Lakehouse:
* **CREATE / CREATE OR REPLACE**: การสร้างตารางใหม่ หรือสร้างแทนที่ตารางเดิมที่มีอยู่แล้ว พร้อมการกำหนด `TBLPROPERTIES` เช่น `delta.enableTypeWidening` และ `delta.columnMapping.mode` เพื่อรองรับฟีเจอร์ของ Delta Table
* **ALTER TABLE**: การแก้ไขตาราง เช่น การเพิ่มคอลัมน์ (`ADD COLUMN`), การลบคอลัมน์ (`DROP COLUMN`), การเปลี่ยนชื่อคอลัมน์ (`RENAME COLUMN`), และการเปลี่ยนประเภทข้อมูล (`ALTER COLUMN TYPE`)
* **TRUNCATE / DROP**: `TRUNCATE` ใช้สำหรับล้างข้อมูลภายในตารางทั้งหมดโดยคงโครงสร้างตารางไว้ ส่วน `DROP` ใช้สำหรับลบตารางออกจากระบบอย่างถาวร

## 2. ภาษาสำหรับการจัดการข้อมูล (DML - Data Manipulation Language)
คำสั่งพื้นฐานในการควบคุมและจัดการข้อมูลในระดับแถว:
* **INSERT INTO**: การเพิ่มข้อมูลใหม่เข้าไปยังตาราง
* **UPDATE / DELETE**: `UPDATE` ใช้แก้ไขค่าของข้อมูลตามเงื่อนไขที่กำหนด และ `DELETE` ใช้สำหรับลบแถวข้อมูลออกจากตาราง
* **SELECT & WHERE Clause**: การดึงข้อมูลและการกรองข้อมูลด้วยเงื่อนไขต่างๆ เช่น `IN`, `BETWEEN`, `IS NULL`, หรือการใช้ Wildcard Matching ด้วย `LIKE` (`%`, `_`)

## 3. การจัดกลุ่มข้อมูลและตัวกรองขั้นสูง (Aggregation & Having)
* **GROUP BY**: การจัดกลุ่มข้อมูลตามคอลัมน์ที่ต้องการเพื่อทำสถิติร่วมกับฟังก์ชัน Aggregate (เช่น `SUM`, `COUNT`, `AVG`, `MIN`, `MAX`)
* **HAVING Clause**: ตัวกรองเงื่อนไขที่ใช้สำหรับคัดเลือกกลุ่มข้อมูล**หลัง**จากการทำ Group By (ต่างจาก `WHERE` ที่กรองข้อมูลก่อนการจัดกลุ่ม)
